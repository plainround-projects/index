# ARCHITECTURE.md against the code: what the drawing sessions found

While drawing the README figures on 2026-11-04, each session checked the edges it drew against the code. Where a document and the code disagreed, the drawing follows the code and nothing was changed in the repository. This is the full list, one place to work from. Items that say "not run" or "not verified" are the session's reading, not a measurement.

## Pilot

- **kafka-order-events:** the doc says the log line is `assigned partitions`; the code logs `partitions assigned` (`kafka_source.py:29`). The Limits section says a malformed event crashes the consumer; the code logs and skips it, as step 6 says.
- **ai-cited-answers:** the doc says vector search is "served by an HNSW index", but the query's `ORDER BY embedding <=> x, id` probably prevents that on Postgres 17 (planner reading, not run). The walk-through leaves out the HTTP 503 path when the model fails. It places the request log at step 1; the code writes it after answering. A docstring says `.env.example`, but the file is `env.example`.
- **gcp-landing-zone-slice:** the Mermaid says the outside bucket is "in another project"; the scripts say outside the organization.

## Batch 1 (AI)

- **ai-event-driven-ai-worker:** the doc orders the webhook as verify the signature, then size-limit; `webhook.py` size-checks the streaming body (413) first, then verifies the signature. From the pilot's blind trial, not re-checked: the deadline check runs before the model call in `handler.py`; `permanent_error` for a generic `ModelCallError` is undocumented.

- **ai-guardrails-and-red-team:** README says "6 benign runs blocked" in step 3 and "7/300" in step 5 (README-internal).

## Batch 6 (Java, Jenkins, Kafka, Kubernetes, microservices)

- **jenkins-controller-as-code:** the Mermaid has the controller checking out from the Git server; the job uses `lightweight(true)`, so the controller fetches only the Jenkinsfile and the agent does the workspace checkout.
- **kafka-idempotent-consumer:** the Mermaid sends the offset commit to the `payments` topic; step 6, the components table and the code commit to the group coordinator.
- **microservices-retry-storm:** the Mermaid has the harness calling `/admin/profile` only on the gateway and `/metrics` only on stock; `tests/system/harness.py` posts the profile to every service and scrapes every service.
- **kubernetes-harden-a-namespace:** the text and Mermaid put ResourceQuota before the validating policy; kube-apiserver runs ValidatingAdmissionPolicy before ResourceQuota, which runs last (upstream behavior, not verified here).

- **security-secure-the-pipeline:** the doc says `VerifyArtifact` gives "one of four named refusals"; `Refusal` has five (`NOT_PINNED`, `UNSIGNED`, `WRONG_IDENTITY`, `DIGEST_MISMATCH`, `UNVERIFIABLE`). - **spring-resilient-client:** steps 2 and 4 disagree on whether the slot is taken before the retry loop or on each retry; both annotations sit on `ProviderCall.attempt` and nothing shows which runs outside (not run).
- **security-threat-model-and-harden:** the doc says `finish` adds the security headers; they come from a separate `after_request` hook, `apply_security_headers`.
